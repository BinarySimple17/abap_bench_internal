1. Оба класса — без побочных эффектов и без БД: вход-строка → выход-структура;

2. Сообщения об ошибках — дословно в стиле исходного бенчмарка (PLAN.md §3/§5:
   «Code structure issue: …», «The syntax check failed with the following
   error: …») — они уйдут модели как фидбек.
3. Уровень 7.54; `make lint` зелёный.

## Задачи

### Task 1: `ZCL_AI_CANON`

Шаги (PLAN.md §3): (1) снять markdown-фенсы — строки из одних бэктиков
(``` + опциональный язык) в начале/конце; (2) найти первое
`CLASS <name> DEFINITION` (case-insensitive) — нет класса → error
«Code structure issue: no ABAP class definition found in your answer…»;
(3) переименовать класс → `lcl_solution` и первый публичный метод →
контрактное имя (`IV_METHOD`), whole-word, case-insensitive — регэксп с
границами слов (ABAP-регэкспы без `\b`: эмулируй через
`(^|[^A-Za-z0-9_])name([^A-Za-z0-9_]|$)` или посимвольный скан); (4) удалить
`PUBLIC` из `DEFINITION`-строки. Выход: канонизированный код + ok/ошибка.

**✅ Самопроверка:** класс в `src/`; на бумаге (в отчёте) прогнать 3 входа из
сценариев MOCK (M03): валидный класс → ok; текст без класса → error; класс с
фенсами → фенсы сняты, ok; lint зелёный.

---

### Task 2: `ZCL_AI_CHECK`

Собрать полный исходник: строка `PROGRAM zai_probe.` + канонизированный код →
`lt_source` (STRING; fallback-режим — конверт в `c length 255`, выбор режима —
константа/настройка, реальная проверка STRING vs c255 — M07, PLAN.md §13.3).
`SYNTAX-CHECK FOR lt_source MESSAGE lv_msg LINE lv_line WORD lv_word PROGRAM
'ZAI_PROBE' DIRECTORY ENTRY ls_trdir` (trdir-subc = '1'). Выход: ok +
сообщение/стра/слово при ошибке. Фидбек-текст — PLAN.md §5.

**✅ Самопроверка:** класс в `src/`; обёртка и fallback оба в коде; lint
зелёный.

## Ловушки

1. Регэксп-переименование: `z_humaneval_solution` содержит
   `humaneval_solution` как подстроку — whole-word обязателен; не заменяй
   внутри строк-литералов и комментариев без необходимости (достаточно
   word-boundary; идеальность не требуется — поведение исходника главное).
2. Несколько классов в ответе — каноникализируй первый (как в исходнике).
3. `SYNTAX-CHECK` не исполняет код и ничего не создаёт (PLAN.md §5) — но всё
   равно не передавай туда ничего, кроме собранного исходника.
4. Удаляй `PUBLIC` только из `CLASS … DEFINITION PUBLIC` — не из
   `CLASS-DATA`/прочих вхождений слова.
