## Задачи

### Task 1: `ZIF_AI_LLM_CLIENT` — контракт

Типы интерфейса: сообщение (`ROLE` char10: system/user/assistant,
`CONTENT` string), таблица сообщений, результат чата (`RESPONSE` string,
`MODEL_VERSION` string, `LATENCY_MS` int4, `TOKENS_IN/OUT` int4). Метод
`chat( it_messages, iv_model_profile ) → ty_chat_result`, исключение
`ZCX_AI_LLM` (инфра-сбой: не «модель ответила плохо», а «не дозвонились»).
Контракт зафиксировать в комментарии интерфейса: без изменений после M05
без ADR.

**✅ Самопроверка:** `.intf.abap/.xml` в `src/`; сигнатура покрывает
PLAN.md §6 (сообщения, latency, tokens, версия модели); lint зелёный.

---

### Task 2: `ZCX_AI_LLM`

Исключение на базе `CX_STATIC_CHECK` с текстом по умолчанию и, при нужде,
полем `DETAIL` (код/причина SDK для лога `ZTAI_ROUND-INFRA_MSG`).

**✅ Самопроверка:** `.clas.abap/.xml` в `src/`; lint зелёный.

---

### Task 3: `ZCL_AI_LLM_MOCK` — сценарии

Сценарий кодируется в `SDK_PROFILE` реестра моделей (формат
`MOCK:<SCENARIO>`): `MOCK:S` — валидный локальный класс `lcl_solution`
(статический метод, простой алгоритм — например НОД из `humaneval_013`),
без markdown-фенсов; `MOCK:X` — код с синтаксической ошибкой (напр.
пропущен `ENDCLASS.`); `MOCK:CANON` — ответ без класса (провал
каноникализации); `MOCK:INFRA` — `RAISE ZCX_AI_LLM`. `MODEL_VERSION` =
профиль, `LATENCY_MS`/`TOKENS_*` — детерминированные константы. Ответ на
попытку >1 в `MOCK:X` — тот же код (диалог честно доходит до maxed out) —
или исправляется с 3-й (обе стратегии покрывают отчётливые картины; выбери и
зафиксируй в комментарии).

**✅ Самопроверка:** класс в `src/`; все 4 сценария реализованы; выбранные
стратегии зафиксированы; lint зелёный.

## Ловушки

1. `utclong`/`cl_abap_tstmp` для метрик времени; `GET RUN TIME` — см.
   PITFALLS #10/#45 (латентность MOCK — константа, замеры — движок, M05).
2. MOCK не читает `ZTAI_MODEL` — профиль приходит параметром; работа с
   реестром — в движке.
3. Формат сообщений = восстановление диалога из `ZTAI_ROUND` (PLAN.md §4.2):
   system + промпт + чередование ответ/фидбек — держи порядок
   user/assistant при формировании.
