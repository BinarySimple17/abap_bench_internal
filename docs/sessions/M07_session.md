# M07 — Деплой в систему и приёмка фазы 1 (сквозной прогон на MOCK)

Этап: Фаза 1 (ADR-006), деплой/приёмка | Владелец: M | Зависимости: M06 | Оценка: — | Статус: [ ] ⬜

## ⚠️ Прочитай перед началом

> Единственная сессия фазы 1, требующая доступа к SAP-системе: перенести
> объекты M01–M06 из `src/` в пакет `ZAI` (abapGit), активировать, закрыть
> системные вопросы §13.3, прогнать сквозной бенчмарк на MOCK вручную и
> посмотреть логи. До этой сессии ничто системное не считается проверенным
> (ADR-006). Выполняется человеком с агентом-консультантом.

### Правила для исполнителя

1. Порядок строгий: активация DDIC → классы/отчёты → SM30-виды → данные
   (настройки/модели) → импорт задач → прогон.
2. Каждое отклонение системы от офлайн-допущений (типы, SYNTAX-CHECK STRING,
   CVERS) — фиксируй сразу: мелкое правкой в `src/` + lint, меняющее решения —
   ADR + правка канона.
3. Транспортный запрос на пакет `ZAI` — один рабочий TR на сессию (ADR-007).
4. По завершении: `make check` зелёный, PLAN.md §13.3 закрыт, сессии M01–M06
   получают фактические подтверждения своих «проверить на M07».

## Задачи

### Task 1: Деплой объектов

abapGit: подключить пакет `ZAI` к этому репозиторию (offline-режим: zip или
локальный путь — как удобнее стенде), pull `src/`, активировать всё.
Порядок внутри: `ZEAI_*` → `ZTAI_*` → `EZ_AI_RUN` → `ZCX_AI_LLM` →
`ZIF_AI_LLM_CLIENT` → `ZCL_AI_*` → отчёты.

**✅ Самопроверка:** лог активации без ошибок; SE11 показывает все объекты
списка PLAN.md §10 (фазы 1); в `src/` нет расхождений с системой (status
abapGit — чистый).

---

### Task 2: SM30-виды + стартовые данные

SE54/SE11: виды обслуживания на `ZTAI_SETT`, `ZTAI_MODEL` (и `ZTAI_TASK` без
STRING-полей — просмотр). Внести: `ZTAI_MODEL` — строки MOCK-сценариев:
`MOCK` / `MOCK:S` / TEMPERATURE 0.2 / ACTIVE; временно для приёмки также
`MOCK_X` (MOCK:X), `MOCK_CANON` (MOCK:CANON), `MOCK_INFRA` (MOCK:INFRA).
Настройки не сеять — дефолты в коде (ADR-006); проверить выборку дефолтов
через SE16 по пустой таблице (косвенно — прогоном).

**✅ Самопроверка:** SM30 открывает виды на запись; 4 строки моделей на месте.

---

### Task 3: Системные проверки §13.3

(a) `CVERS`/`SAP_BASIS` + SP: сверить с целевым NW 7.54 (ADR-003);
расхождение → остановиться, ADR + правка `syntax.version`/§3. (b) Проба
`SYNTAX-CHECK FOR itab` с STRING-таблицей (валидный мини-исходник): если
падает — переключить константу в `ZCL_AI_CHECK` на c255 (правка в `src/` +
lint + ре-деплой класса).

**✅ Самопроверка:** оба пункта закрыты с фактическими значениями в отчёте.

---

### Task 4: Импорт задач

`ZAI_IMPORT_TASKS` (диалог): загрузить все 10 `tasks/*.task.txt`. Повторный
импорт без изменений — `task_version` не растёт. Править один файл (например
пробел в CANONICAL) + реимпорт — растёт; откатить файл и реимпортом вернуть.

**✅ Самопроверка:** `ZTAI_TASK` — 10 активных строк; повторный импорт
идемпотентен; `TASKSET_HASH` стабилен между идентичными импортами.

---

### Task 5: Сквозной прогон и resume

`ZAI_RUN`: новый прогон, все 4 MOCK-модели, REPETITIONS=2, MAX_ATTEMPTS=3
(компактно). Ожидания: `MOCK` → S; `MOCK_X` → X; `MOCK_CANON` → X (раунды с
CANON_OK=abap); `MOCK_INFRA` → I. `ZAI_STATUS`: итоги и раунды читаемы,
drill-down до RESPONSE_RAW работает. Resume: прервать прогон (отмена job/
сессии на середине — любое средство), перезапустить `ZAI_RUN` с тем же
RUN_ID — докручивает только недостающее, финальные строки не тронуты.

**✅ Самопроверка:** все четыре статуса воспроизведены; логи видны; resume
идемпотентен; `ZTAI_RUN` закрылся STATUS='S'.

## Ловушки

1. Активация DDIC пачкой может требовать порядка — если abapGit-активатор
   ругается, активируй слоями (Task 1 порядок).
2. `SUPPRESS_DIALOG`/фон: импорт и прогон в фоновом режиме — только после
   диалоговой отладки; CTS-попапы в фоне — PITFALLS #14–#19, секция DDIC.
3. MOCK-сценарии `MOCK:X/CANON/INFRA` после приёмки деактивировать
   (`ACTIVE=''`), оставив рабочую `MOCK` — иначе фаза 2-прогоны будут
   тащить мусор.
4. Если STRING-проба провалилась и включён c255 — длинные строки канона
   режутся по 255: проверь в логах, что фидбек модели остаётся осмысленным.
