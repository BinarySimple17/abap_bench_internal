## ⚠️ Прочитай перед началом

> Первый этап реализации в SAP-системе: создать DDIC-таблицы `ZLLBM_*` (PLAN.md
> §4.2), настройки `ZLLBM_SETT` (§4.3) с system prompt из §3, парсер/импорт задач
> `ZCL_LLBM_TASKS` + отчёт `ZLLBM_IMPORT_TASKS`, реестр моделей `ZLLBM_MODEL`,
> интерфейс `ZIF_LLBM_LLM_CLIENT` и `ZCL_LLBM_LLM_MOCK`. Попутно закрываются
> открытые вопросы §13, решаемые на M1: пакет, стартовые модели, фактический
> релиз системы, STRING в `SYNTAX-CHECK FOR itab`. Критерий приёмки этапа —
> §11: импорт 10 задач из файла; настройки и модели редактируются; MOCK отвечает.
> SDK-адаптер `ZCL_LLBM_LLM_SDK` в сессию НЕ входит — исходники SDK ещё не
> получены, отладка идёт на MOCK.

### Правила для исполнителя

1. Весь ABAP — уровень до 7.54 (система NW 7.54, [ADR-003](../adr/ADR-003-nw-754.md)):
   конструкции 7.55+ запрещены (например, `FINAL(...)`, 7.57); локальный гейт —
   abaplint v754 ([ADR-002](../adr/ADR-002-abaplint-gate.md), `make lint`),
   окончательная проверка — система (PLAN.md §3).
2. Имена объектов — строго по PLAN.md §10; новые/переименованные объекты —
   только через ADR + синхронную правку PLAN.md.
3. Всё, что выполняется в SAP, фиксируется в «Отчёте» сессии (пункт «Проверить
   в системе»); репозиторий получает только документы — файл сессии, ADR,
   правки PLAN.md. Код ABAP в этот репозиторий не складывается.
4. Содержимое задач `tasks/*.task.txt` не меняется; импорт в системе — по
   правилу upsert + `task_version` (PLAN.md §4.1).
5. Перед написанием ABAP — сверяйся с [docs/ABAP-PITFALLS.md](../ABAP-PITFALLS.md);
   найденные новые грабли фиксируются в нём в тот же день (нумерация N65+).

## Предусловия

- [ ] Доступ к dev-системе есть; фактический релиз подтверждён (`CVERS`: SAP_BASIS + SP) и совпадает с целевым NW 7.54 (ADR-003); при расхождении — ADR + синхронная правка `syntax.version` и PLAN.md §3 (PLAN.md §13.5)

- [ ] `make check` в репозитории зелёный; 10 задач в `tasks/` проходят `make check-tasks`

## Задачи

### Task 1: DDIC-таблицы, lock-объект, SM30-виды

Создать 6 таблиц `ZLLBM_TASK`, `ZLLBM_MODEL`, `ZLLBM_RUN`, `ZLLBM_ROUND`,
`ZLLBM_RESULT`, `ZLLBM_SETT` по PLAN.md §4.2 (ключи и поля — из таблицы §4.2;
STRING-колонки → LOB-типы). Lock-объект `EZ_LLBM_RUN`. SM30-виды: `ZLLBM_SETT`,
`ZLLBM_MODEL` (и `ZLLBM_TASK` без STRING-полей — §10). Заполнить `ZLLBM_SETT`
дефолтами §4.3, включая `SYSTEM_PROMPT` (текст §3 с плейсхолдером версии NW,
`NW_VERSION` = «NetWeaver 7.54 (AS ABAP 7.54)» — ADR-003).

**✅ Самопроверка:** все объекты активированы без ошибок (полный лог);
SE16 показывает структуры; SM30 открывает виды настроек и моделей на запись.

---

### Task 2: `ZCL_LLBM_TASKS` + `ZLLBM_IMPORT_TASKS`

Парсер формата файла задачи (PLAN.md §4.1): мета-строки `@id/@source/@method/
@category/@active` + секции `---PROMPT---`/`---CANONICAL---`/`---TEST---`.
Импорт — upsert по `@id`: новое содержание → `task_version + 1`; расчёт
`TASKSET_HASH` (хэш отсортированного списка id+version активных задач).
Диалоговый режим — выбор файла; фоновый — каталог на сервере приложений.

**✅ Самопроверка:** импорт всех 10 задач из `tasks/`: в `ZLLBM_TASK` 10 строк;
повторный импорт без изменений не увеличивает `task_version`; правка файла +
реимпорт увеличивает.

---

### Task 3: `ZIF_LLBM_LLM_CLIENT` + `ZCL_LLBM_LLM_MOCK`

Интерфейс `chat(...)`: сообщения диалога → ответ модели + latency + tokens +
версия модели (PLAN.md §6). `ZCL_LLBM_LLM_MOCK` — детерминированные ответы для
отладки движка (M2): сценарий S (валидный локальный класс `lcl_solution`),
сценарий сбоев каноникализации (ответ без класса/с фенсами), сценарий
инфра-сбоя (диагностируемая ошибка для ретраев). Исключение `ZCX_LLBM_LLM`
для инфра-сбоев SDK.

**✅ Самопроверка:** smoke-вызов MOCK через интерфейс возвращает ответ и
метаданные; все три сценария воспроизводятся (полная проверка в цикле движка —
M2).

## Ловушки

1. `SYNTAX-CHECK FOR itab` может не принимать таблицу строк типа STRING —
   проверить на системе первой же пробой; при отказе — паддинг в `c length 255`
   (PLAN.md §5, §13.5). Это влияет на Task 2/3 минимально, но блокирует M2.
2. STRING-поля — это LOB: не могут быть ключевыми, SM30 их не редактирует.
   Содержимое задач правится только реимпортом, вид на `ZLLBM_TASK` — без
   STRING-полей (PLAN.md §10).
3. Фактический релиз может отличаться от NW 7.54 — сверить с CVERS до
   написания кода; расхождение → ADR + правка `syntax.version` (ADR-002/003,
   PLAN.md §3).
4. `TASKSET_HASH` считать детерминированно (сортировка + хэш id+version) —
   на нём держится сравнимость трендов (PLAN.md §4.1).
5. Temperature в `ZLLBM_MODEL` — дефолт 0.2 (как в исходном бенчмарке), но
   выбор стартовых моделей — решение владельца §13.2, не заполняй сам.
6. Перед созданием DDIC-объектов — свериться с
   [ABAP-PITFALLS §DDIC](../ABAP-PITFALLS.md) (#14–#19: REFKIND на
   builtin-типах, TABNAME/POSITION в DD03P, у `DDIF_*_PUT` нет RC, UNAME в
   `DWINACTIV` обязателен, CTS-попапы в фоне — `SUPPRESS_DIALOG`).
