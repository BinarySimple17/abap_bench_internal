# ADR-004: Конвенция имён SAP-объектов — схема `Z*AI_*`

- **Статус:** Принято (2026-10-14); v2 (2026-10-14) — имя `ZCL_AI_LLM_SDK` из таблицы переименования уточнено до `ZCL_AI_LLM_SDK_PROXY` ([ADR-005](ADR-005-llm-sdk.md))
- **Дата:** 2026-10-14
- **Контекст принятия:** до старта M1 владелец задал конвенцию префиксов, заменяющую прежний неймспейс `ZLLBM_*` из PLAN.md §10
- **Связанные документы:** `PLAN.md` §10 (синхронно правится этим ADR), §4.2; сессия M01

---

## 1. Контекст

Все объекты бенчмарка именовались в едином неймспейсе `ZLLBM_*` (таблицы
`ZLLBM_*`, классы `ZCL_LLBM_*`, интерфейс `ZIF_LLBM_*`, исключения
`ZCX_LLBM_*`, отчёты `ZLLBM_*`, FM `Z_LLBM_*`, lock `EZ_LLBM_RUN`). В
системе ещё не создано ни одного объекта (старт реализации — M1), поэтому
переименование ничего не стоит: нет ни транспортов, ни данных, ни ссылок в
коде. Содержимое задач имена объектов не использует (канонический класс —
локальный `lcl_solution`), поэтому `TASKSET_HASH` и сравнимость трендов не
затрагиваются.

## 2. Решение

**Конвенция задана владельцем (2026-10-14):**

| Категория | Префикс |
|---|---|
| Классы | `ZCL_AI_*` |
| Таблицы БД | `ZTAI_*` |
| Элементы данных | `ZEAI_*` |
| Словарные структуры | `ZSAI_*` |

**Производные по той же схеме** (без отдельных решений; при потребности —
домены `ZDAI_*`): интерфейсы `ZIF_AI_*`, исключения `ZCX_AI_*`, отчёты
`ZAI_*`, FM `Z_AI_*`, lock-объекты `EZ_AI_*`.

**Таблица переименования** (старое → новое, синхронно внесено в PLAN.md §10):

| Было (`ZLLBM_*`) | Стало |
|---|---|
| Таблицы `ZLLBM_TASK`, `ZLLBM_MODEL`, `ZLLBM_RUN`, `ZLLBM_ROUND`, `ZLLBM_RESULT`, `ZLLBM_SETT` | `ZTAI_TASK`, `ZTAI_MODEL`, `ZTAI_RUN`, `ZTAI_ROUND`, `ZTAI_RESULT`, `ZTAI_SETT` |
| Lock `EZ_LLBM_RUN` | `EZ_AI_RUN` |
| Интерфейс `ZIF_LLBM_LLM_CLIENT` | `ZIF_AI_LLM_CLIENT` |
| Классы `ZCL_LLBM_ENGINE`, `ZCL_LLBM_CANON`, `ZCL_LLBM_CHECK`, `ZCL_LLBM_LLM_SDK`, `ZCL_LLBM_LLM_MOCK`, `ZCL_LLBM_ASSERT`, `ZCL_LLBM_TASKS` | `ZCL_AI_ENGINE`, `ZCL_AI_CANON`, `ZCL_AI_CHECK`, `ZCL_AI_LLM_SDK`, `ZCL_AI_LLM_MOCK`, `ZCL_AI_ASSERT`, `ZCL_AI_TASKS` |
| Исключения `ZCX_LLBM_LLM`, `ZCX_LLBM_ASSERT` | `ZCX_AI_LLM`, `ZCX_AI_ASSERT` |
| Отчёты `ZLLBM_RUN`, `ZLLBM_IMPORT_TASKS`, `ZLLBM_STATUS`, `ZLLBM_REPORT`, `ZLLBM_SCHEDULE_JOB` | `ZAI_RUN`, `ZAI_IMPORT_TASKS`, `ZAI_STATUS`, `ZAI_REPORT`, `ZAI_SCHEDULE_JOB` |
| FM `Z_LLBM_RUN_TESTS` | `Z_AI_RUN_TESTS` |
| Временная программа `ZLLBM_PROBE` / `zllbm_probe` | `ZAI_PROBE` / `zai_probe` |
| Пакет (кандидат, §13.1 — вопрос открыт) | `ZAI` (вместо `ZLLBM`) |

Синхронные правки этим ADR: `PLAN.md` (§2, §4.2, §5, §7, §9, §10, §11, §12,
§13), `AGENTS.md`, `Makefile`, `docs/sessions.md`, `docs/sessions/M01_session.md`.

Последствия: положительные — единая схема «Z + типовая буква + AI», имена
короче; исчезает коллизия «таблица и отчёт с одним именем» (было `ZLLBM_RUN`
в обеих ролях) — теперь `ZTAI_RUN` и `ZAI_RUN`. Отрицательные/риски — инфикс
`AI` ходовой, выше шанс занятости имён в системе: при создании каждого
объекта проверять занятость (SE11/SE80); при коллизии — ADR. abaplint
`errorNamespace` (`^(Z|Y|LCL_|TY_|LIF_)`) покрывает новые префиксы без
правки (ADR-002).

## 3. Сравнение по осям решения

| Ось | `Z*AI_*` (принято) | `ZLLBM_*` (прежде) |
|---|---|---|
| Тип объекта виден в префиксе | да (T/E/S + AI, CL/IF/CX) | частично (только CL/IF/CX) |
| Длина имён | короче на 2 символа | длиннее |
| Уникальность в системе | ниже («AI» ходовой инфикс) | выше («LLBM» специфичнее) |

**Итог сверки:** решающая ось — решение владельца о схеме имён; риск
коллизий купируется проверкой занятости имён при создании на M1.

## 4. Рассмотренные варианты

### Вариант A — оставить `ZLLBM_*`
Отвергнут владельцем.

### Вариант B — схема `Z*AI_*` ✅ **ПРИНЯТО**
Основание: §2. Все ссылки в каноне переименованы синхронно с этим ADR;
появились первые категории, у которых префиксы раньше не были зафиксированы
(элементы данных `ZEAI_*`, структуры `ZSAI_*`).
