# ADR-003: Целевая версия системы — NW 7.54 (вместо NW 7.42)

- **Статус:** Принято (2026-10-14)
- **Дата:** 2026-10-14
- **Контекст принятия:** при подключении abaplint (ADR-002) владелец решил целиться в ту же dev-систему, что у zvvvv-abab-vectors — NW 7.54 (`syntax.version v754`), отменив зафиксированное в PLAN.md §1 допущение NW 7.42 / ABAP 7.40
- **Связанные документы:** `PLAN.md` §1/§3/§4.3/§13 (синхронно правится этим ADR), ADR-002 (lint-гейт v754)

---

## 1. Контекст

Версия NW 7.42 была зафиксирована консервативно до уточнения стенда (PLAN.md
§1). Она определяла три вещи: языковой уровень нашего Z-кода, допустимые
конструкции в system prompt для LLM и дефолт настройки `NW_VERSION`. Фактическая
dev-система бенчмарка — та же, на которой ведётся zvvvv-abab-vectors
(NW 7.54); прогоны бенчмарка ещё не начинались, поэтому смена версии не
ломает сравнимость трендов.

## 2. Решение

**Целевая версия — NetWeaver 7.54.** Языковой уровень нашего Z-кода и
генерируемого кода — всё до 7.54 включительно; конструкции 7.55+ запрещены
(например, `FINAL(...)`, 7.57). Синхронные правки: PLAN.md §1 (решение), §3
(языковой уровень: разрешены CTE `WITH` — 7.50 и оконные функции — 7.54),
§4.3 (дефолт `NW_VERSION` = «NetWeaver 7.54 (AS ABAP 7.54)»), §13 (закрыто);
гейт abaplint — `syntax.version = v754` (ADR-002).

Последствия: положительные — соответствие фактическому стенду; system prompt
ближе к исходному бенчмарку (там 7.57), меньше искусственных ограничений на
SQL; отрицательные/риски — модели с более старыми знаниями могут чаще
ошибаться на 7.5x-конструкциях (это корректный сигнал, не шум); abaplint не
жёстко отсекает все 7.55+ (см. ADR-002 §2) — дисциплина + система как
арбитр. Критерий пересмотра: смена стенда бенчмарка.

## 3. Сравнение по осям решения

| Ось | NW 7.54 (как там) | NW 7.42 (прежде) | NW 7.57 (как в исходном бенчмарке) |
|---|---|---|---|
| Соответствие фактической системе | да | нет (выдуманный стенд) | нет |
| Возможности для кода | ≤7.54 | ≤7.40 | ≤7.57 |
| Сравнимость с исходным бенчмарком | ближе (но версия объявляется явно) | дальше | точное совпадение, но не наша система |

**Итог сверки:** решающая ось — соответствие фактическому стенду; сравнимость
с исходником обеспечивается дословностью промптов и явным `NW_VERSION` в
system prompt, а не совпадением версии.

## 4. Рассмотренные варианты

### Вариант A — остаться на NW 7.42
Отвергнут. Стенд другой; ограничение 7.40 было бы искусственным и сразу
наткнулось бы на M1-сверку CVERS (PLAN.md §13.5).

### Вариант B — поднять сразу до 7.57, как в исходном бенчмарке
Отвергнут. Не соответствует нашей системе; синтакс-чек на 7.57-конструкциях
давал бы ложные сбои.

### Вариант C — NW 7.54 (та же система, что у zvvvv-abab-vectors) ✅ **ПРИНЯТО**
Основание: см. §2. Версия объявляется модели явно через `NW_VERSION` —
корректный сигнал бенчмарка сохраняется.
