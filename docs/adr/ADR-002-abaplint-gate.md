# ADR-002: Подключение abaplint как гейта ABAP-кода

- **Статус:** Принято (2026-10-14)
- **Дата:** 2026-10-14
- **Контекст принятия:** в репозитории появится ABAP-код (выгрузка abapGit в `src/`); нужен статический контур верификации до переноса в систему — по образцу zvvvv-abab-vectors
- **Связанные документы:** ADR-001 (харнесс; отличие №2 — «без abaplint» — этим ADR отменяется), ADR-003 (целевая версия NW 7.54), `harness/README.md`

---

## 1. Контекст

ABAP-код создаётся в SAP-системе и попадает в репозиторий только через выгрузку
abapGit. До этого ADR единственная автоматическая верификация — python-гейты
харнесса, которые ABAP не проверяют вовсе: ошибка синтаксиса/нейминга
обнаруживалась бы только при активации в системе (у владельца, вручную).

## 2. Решение

**abaplint 2.120.x как dev-зависимость Node (`@abaplint/cli`), два конфига и
make-таргеты — конфигурация перенесена у zvvvv-abab-vectors дословно, кроме
`syntax.version` (см. ADR-003).** `abaplint.json` — блокирующий гейт (семантика,
parser-error, xml_consistency, naming), входит в `make check` и
`make verify-session`; `abaplint-all.json` — широкий репорт (не блокирует).
Вызовы — `make lint` / `make lint-all`. При отсутствии файлов в `src/` гейт
пропускается с сообщением (нечего проверять) — baseline остаётся зелёным до
первой выгрузки.

Последствия: положительные — ABAP проверяется локально, до системы; регресс
абаплинт-конфига ловится `make check`; отрицательные/риски — Node.js
dev-зависимость (только локальная верификация, в систему не попадает);
abaplint не знает DDIC целевой системы (часть правил — только в репорте,
см. комментарии в конфигах).

**Известное ограничение (проверено на 2.120.77):** `syntax.version` задаёт
базлайн парсера и правил, но **не жёстко отсекает все конструкции новее** —
`FINAL(...)` (7.57) под v754 не ловится. Запрет 7.55+ остаётся правилом
кодирования (AGENTS.md) и предметом ревью; авторитетная верификация версии —
система (syntax-check/активация).

## 3. Сравнение по осям решения

| Ось | abaplint-гейт | Только python-гейты (как в ADR-001) | Вывод |
|---|---|---|---|
| Верификация ABAP | синтаксис/парсер, naming, xml/DDIC-консистентность | нулевая | решающая ось |
| Зависимости | Node.js (dev, локально) | только python stdlib | приемлемо |
| Согласованность с исходником | та же конфигурация, тот же опыт | своя придумка | перенос проверенного |

**Итог сверки:** ось верификации критична с появлением ABAP; цена — одна
dev-зависимость.

## 4. Рассмотренные варианты

### Вариант A — без линтера, проверка только в системе
Отвергнут. Ошибки находились бы владельцем при активации, цикл обратной связи
слишком длинный.

### Вариант B — abaplint только как репорт (без гейта)
Отвергнут. Нет блокирующего контура — «сломанный» ABAP проходит `make check`.

### Вариант C — abaplint-гейт как в zvvvv-abab-vectors + пропуск на пустом src/ ✅ **ПРИНЯТО**
Основание: см. §2. Конфиги и правила — дословно у исходника; синтакс-версия
привязана к целевой системе (ADR-003).
