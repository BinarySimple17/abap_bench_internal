# Грабли ABAP/A4H — база знаний агента

Живой список проблем, встреченных при работе с ABAP (целевой релиз 7.54, та же
dev-система, что у этого проекта) и способах их обхода. Цель — не переоткрывать
одно и то же. База перенесена из проекта zvvvv-abab-vectors
(`F:/JAVA/zvvvv-abab-vectors/docs/ABAP-PITFALLS.md`) дословно: нумерация и
формулировки сохранены; ссылки на сессии B*/V*, BL-номера и их артефакты —
из проекта-источника. Наши находки дополняют список с трассировкой на
`docs/sessions/M*` (номера продолжают сквозную нумерацию — N65+).

Пополнение: каждая новая грабля фиксируется здесь в тот же день, когда найдена
(пункт отчёта сессии). Семантика языка/ABAP SQL перед правкой сверяется с
официальной документацией (abapdocu на help.sap.com) и официальным читшитом SAP
[abap-cheat-sheets](https://github.com/SAP-samples/abap-cheat-sheets) —
локальная копия: `docs/reference/abap-cheat-sheets/`, маршрутизация «тема →
файл»: `docs/reference/README.md`
(`03_ABAP_SQL.md` — выражения, агрегаты, деление; демо-классы в тексте доки,
например `CL_DEMO_SQL_EXPR_ARITH`): гейт-линт семантику SQL-выражений не
проверяет (#13, #64).

Применимость разделов: «Язык ABAP (7.54)» и «DDIC» — универсальны (для этого
проекта особенно #13, #47, #48, #49, #51 — динамика, генерация кода, фоновые
джобы SM36 — ядро бенчмарка; #10/#45 — замеры LATENCY_MS; #43/#42/#50 — HTTP
для LLM SDK). «A4H / ADT MCP» — тулчейн записи объектов проекта-источника;
актуален в той мере, в какой используется тот же путь записи.

## Язык ABAP (7.54)

| # | Грабля | Обход |
|---|--------|-------|
| 1 | **`SORT itab.` без `BY` — no-op** на таблицах, объявленных `... WITH EMPTY KEY` (ядро 7.54): предупреждение «empty primary key — check semantics», порядок не меняется. Ломает любые перцентили/медианы. | `SORT lt BY table_line ASCENDING.` Для структурных строк — явный `BY поле`. |
| 2 | **`cl_osql_test_environment` — тестовый класс** (FOR TESTING): статическая ссылка на него из main-кода не компилируется («reference to a test class is only possible in test classes»). | OSQL-окружение создаётся в `class_setup` тест-инклюда; рабочий класс получает флаг режима (например `use_doubles( )`). |
| 3 | **Вызов метода через интерфейсно-типизированную ссылку**: `lo_ref->zif_x~meth( )` не компилируется («does not contain an interface»). | Для `REF TO zif_x` — просто `lo_ref->meth( )`. Форма с префиксом — только для ссылок, типизированных классом. |
| 4 | **Целочисленное деление `i / i`** округляет до целого (`2 / 3 = 1`). Результат выражения не зависит от типа приёмника. | `iv_num / CONV f( iv_den )`. Особенно коварно в агрегатах метрик (recall = hits/n). |
| 5 | **`SELECT ... INTO CORRESPONDING FIELDS`** маппит по именам: колонка `OBJ` не попадёт в поле `docid` — молча останется пустым. | Алиас в SELECT: `SELECT id, obj AS docid ...`. Локальный линт это не ловит. |
| 6 | **Литералы в конструкторах типизированных таблиц**: `VALUE tt_embedding( ( 1 ) )` при строковом типе `p10,9` — ошибка «type I is not compatible». | `CONV zcl_...=>ty_coordinate( 1 )` внутри скобки строки. |
| 7 | **`BIT-XOR '80'`** — символьный литерал в бит-выражении не проходит («must have the type X or XSTRING»). | Константа `CONSTANTS lc TYPE x VALUE '80'.` |
| 8 | **Строгая типизация именованных параметров**: фактический `STRING` к формальному `c`/DDIC-полю (и наоборот C→STRING) — ошибка на 7.54. | `CONV ztvvvv_vctr_gold-gold_set( lo->name( ) )`, `CONV string( p_param )`. |
| 9 | `ln( )` не существует; **`log( )` — натуральный**. log2 = `log( x ) / log( 2 )`. | — |
| 10 | `GET RUN TIME FIELD` даёт **микросекунды** (int8): `/1000` — миллисекунды, `/1000` ещё раз — не нужно. Вывод всегда подписывай единицами: перепутанные «мкс/мс» искажают микробенчмарки на 3 порядка. | `data(lv_ms) = ( lv_t1 - lv_t0 ) / 1000. " мс` |
| 11 | `PERFORM` запрещён в классах (в т.ч. в runSnippet). | Только методы. |
| 12 | Inline-объявление `DATA(...)` **не во всех позициях**: `IMPORTING key = DATA(x)` у FM — ошибка. | Объявить заранее. |
| 13 | abaplint (наш гейт) с выключенными `check_syntax`/`unknown_types` (из-за SDK-объектов вне git) **не ловит** неизвестные переменные/типы/сигнатуры — все «Field ... is unknown» всплывают только при активации в системе. | Считать локальный lint проверкой стиля, не компилятором; первое включение в систему = первая настоящая компиляция. |
| 47 | **`INSERT REPORT` не проверяет синтаксис** — сгенерированная программа падает `SYNTAX_ERROR` уже в джобе (B05: несуществующее поле `ls_stats-points`), а логические no-op (SORT по EMPTY KEY, #1) не ловит никто: генератор-строки в исходнике класса компилятор не видит. | После `INSERT REPORT` — синтакс-чек по source URL сгенерированной программы (ADT `syntaxCheckCode`) ДО планирования джобы. |
| 48 | **Экран выбора/вариант SM36 поднимает регистр string/CHAR-параметров** (без `LOWER CASE`): сид `…|text-…` с экрана становится `…|TEXT-…`, конкатенация set+model без pipe даёт третий вариант — BID-дрейф, корзина «теряется» (B05: три разных BID из одного сида, рабочая оказалась с верхним регистром). | Сид-чувствительные параметры — с `LOWER CASE` (или сид из upper-устойчивых компонентов); диагностика «куда записалось» — `SELECT bid, COUNT(*) FROM ztvvvv_vctr GROUP BY bid`. |
| 52 | **Константа, упомянутая в публичной сигнатуре, обязана лежать в PUBLIC-секции** — `c_cache_max` в PRIVATE роняла активацию сигнатуры `new( iv_cache_limit = … )`. abaplint (см. #13) такое не ловит — ловит только активация. | Константы дефолтов публичных параметров — PUBLIC; «зелёный lint» ≠ «компилируется». |

## Полезные рецепты (проверены)

- **Диагностика «странного» рантайма**: маркерная правка метода (например `p99 = 42`) → прогон → если маркер не виден, код не тот; если виден — логика в коде, искать семантику (пример #1: SORT-noop).
- **Чтение фактического кода активного класса**: `READ REPORT '<CLAS>====CM00x' INTO ...` (список инклюдов — `SELECT name FROM trdir WHERE name LIKE '<CLAS>%'`).
- **Сигнатуры FM**: `SELECT parameter, structure FROM fupararef WHERE funcname = '...'`.
- **Полный состав неактивного**: `SELECT object, obj_name FROM dwinactiv WHERE obj_name LIKE ...`.
