# Беклог проекта — abap_bench_internal

Папка для всего, что **вне скоупа текущих сессий** (`docs/sessions/`): найденные
по ходу работ задачи, отложенные улучшения, идеи, вопросы. Беклог — место
хранения, а не замена планированию: то, что влияет на приёмку сессии, остаётся
в сессии/каноне продукта (`PLAN.md`), а не уходит сюда.

## Приоритет источников

1. `PLAN.md` (канон) → 2. `docs/adr/` → 3. `docs/sessions/` → **4. элементы беклога** —
они не переопределяют решения, а предлагают будущие.

## Формат элемента

Один файл на элемент: `backlog/items/<ID>-<краткое-имя>.md`, где `<ID>` =
`BL-<номер>` (сквозная нумерация, не переиспользуется).

Последний занятый номер: **BL-2** — каждый новый элемент берёт следующий номер (сейчас BL-3)
и обязан обновить эту строку в том же коммите. Счётчик учитывает и архивные элементы
(номера не переиспользуются, даже если элемент закрыт и уехал в архив); соответствие
счётчика максимальному известному номеру проверяет `harness/scripts/backlog_archive.py --check`.

```markdown
# BL-N: <Название>

- **Тип:** задача | улучшение | идея | вопрос | техдолг
- **Приоритет:** P0 | P1 | P2 | P3 (P0 — блокирует выпуск … P3 — «когда-нибудь»)
- **Состояние:** новый | в работе | заблокирован | отклонён | перенесён (куда) | закрыт (+дата)
- **Владелец:** <трек/имя>
- **Источник (трассировка):** ссылка на канон/ADR/сессию/решение аудита —
  элемент без трассировки к документу помечается «идея»
- **Зависимости:** другие BL / сессии

## Что сделать
<Суть в 3–10 строках; если элемент вырастает в сессию — шаблон docs/sessions/_template.md>

## Критерий закрытия
<Как поймём, что готово; если проверяемо тестом/командой — указать>

## Контекст и альтернативы
<Почему так, что отвергнуто; при зрелости элемента — заготовка для будущего ADR>
```

## Жизненный цикл

1. **Заведение:** обнаружил вне скоупа → файл по формату → упомянуть в отчёте сессии (секция «Перенесено в другие сессии» → там ссылка на BL).
2. **Разбор:** на точках синхронизации треков или на вехах — приоритизировать: сделать сейчас / оставить / отклонить с причиной.
3. **Повышение в сессию:** если элемент блокирует трек — оформить сессию по шаблону, добавить в индекс `docs/sessions.md`, BL пометить «перенесён → <ID сессии>».
4. **Решение вместо задачи:** если элемент меняет архитектуру — сначала ADR, задача ссылается на ADR.
5. **Гигиена:** закрытые и отклонённые элементы не удаляются — их строки переносятся в [archive.md](archive.md) скриптом `harness/scripts/backlog_archive.py` (файл BL остаётся — история решений); ниже поддерживается карта только активных элементов.
6. **Синхронизация:** новый номер BL выделять после свежей сверки карт; счётчик обязан совпадать с максимальным известным номером (README + архив) — проверяется `--check`.
